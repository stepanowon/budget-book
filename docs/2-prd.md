## 1. 제품 개요

### 1.1 배경 및 문제 정의

기존 가계부 앱은 **단일 사용자**만 지출을 입력하는 구조로 설계되어 있다. 여행, 가족 생활비, 정기 모임처럼 여러 명이 함께 지출이 발생하는 상황에서는 다음과 같은 불편이 생긴다.

| 문제 | 현재 상황 | 사용자 영향 |
|------|----------|-----------|
| 지출 입력 분산 불가 | 한 명이 모든 지출을 입력해야 함 | 입력 누락, 관리 부담 집중 |
| 정산 계산 수작업 | 카카오톡·메모장 등으로 수기 계산 | 계산 오류, 시간 소모 |
| 지출 이력 공유 불가 | 그룹 전체가 지출 내역 확인 불가 | 투명성 부족, 신뢰 문제 |
| 그룹별 관리 불가 | 여행/가족/모임을 하나로 관리 | 카테고리 혼재, 정산 복잡 |

### 1.2 제품 설명

**공동 가계부**는 그룹을 생성하고 멤버를 초대하여 **여러 사람이 함께 지출을 입력하고 투명하게 공유하며 쉽게 정산**할 수 있는 웹 서비스다.

- 플랫폼: 웹 / 모바일 웹 (반응형)
- 주요 사용 시나리오: 여행 경비 관리, 가족 생활비 공동 관리, 정기 모임 회비 정산

## 2. 제품 비전 및 목표

### 2.1 제품 비전

> "함께 쓰는 돈, 누구나 쉽게 기록하고 공정하게 정산한다."

그룹 내 모든 멤버가 동등하게 지출을 기록하고, 언제든지 투명하게 확인하며, 클릭 한 번으로 정산할 수 있는 환경을 제공한다.

### 2.2 비즈니스 목표

| 목표 | 지표 | 달성 기준 |
|------|------|----------|
| 서비스 사용자 확보 | 가입자 수 | 출시 6개월 내 MAU 500명 |
| 핵심 기능 활성화 | 그룹 생성 수 | 출시 6개월 내 활성 그룹 200개 |
| 사용자 유지 | 재방문율 | 가입 후 30일 재방문율 40% 이상 |
| 핵심 가치 전달 | 정산 실행 수 | 월 정산 실행 건수 300건 이상 |

### 2.3 핵심 가치 제안 (Value Proposition)

- **공동 입력**: 그룹 내 누구나 지출을 직접 입력 → 한 사람의 부담 제거
- **투명한 공유**: 그룹 멤버 전체가 모든 지출 내역 실시간 조회
- **쉬운 정산**: N빵 자동 계산 + 기간 지정 정산으로 수기 계산 완전 대체
- **유연한 그룹**: 기간 한정(여행)/상시(가족) 두 가지 그룹 타입 지원

## 3. 사용자 페르소나

### P-01. 여행 기획자 — "철저한 준비파 여행 총무"

| 항목 | 내용 |
|------|------|
| 이름 | 김지수 (28세, 직장인) |
| 그룹 유형 | 여행 그룹 (`LIMITED`) |
| 사용 기기 | 스마트폰 (iOS) |
| 기술 친숙도 | 높음 |

**상황**: 5명이 3박 4일 제주도 여행을 계획 중. 매번 여행마다 총무를 맡아 정산이 번거롭다.

**니즈**:
- 여행 기간 한정으로 그룹을 생성하고 멤버를 쉽게 초대하고 싶다.
- 식비·교통·숙소 카테고리별로 지출이 자동 분류되길 원한다.
- 여행 후 버튼 클릭 한 번으로 누가 얼마를 받아야 하는지 바로 알고 싶다.

**페인 포인트**: 카카오톡 정산봇은 지출 카테고리도 없고, 나중에 찾아보기 어렵다.

---

### P-02. 살림 담당자 — "꼼꼼한 가족 재무 담당"

| 항목 | 내용 |
|------|------|
| 이름 | 박민준 (42세, 자영업) |
| 그룹 유형 | 가족 그룹 (`UNLIMITED`) |
| 사용 기기 | PC + 스마트폰 병행 |
| 기술 친숙도 | 중간 |

**상황**: 배우자와 함께 생활비를 분담하는데, 월말마다 각자 쓴 금액을 엑셀로 정리한다.

**니즈**:
- 배우자와 함께 지출을 입력하고 월별 정산을 정기적으로 실행하고 싶다.
- 카테고리별 지출 차트로 이번 달 지출 패턴을 시각적으로 확인하고 싶다.
- 정산 내역을 엑셀로 내보내 보관하고 싶다.

**페인 포인트**: 지금은 카카오톡으로 영수증 사진을 주고받아 금액을 수기로 합산한다.

---

### P-03. 모임 총무 — "정기 모임 경비 관리자"

| 항목 | 내용 |
|------|------|
| 이름 | 이수연 (35세, 회사원) |
| 그룹 유형 | 정기 모임 그룹 (`UNLIMITED`) |
| 사용 기기 | 스마트폰 (Android) |
| 기술 친숙도 | 중간 |

**상황**: 10명 규모의 독서 모임 총무. 매월 모임 후 식사비·장소 대여비를 정산해야 한다.

**니즈**:
- 모임 멤버가 각자 지출을 입력해 총무 혼자 다 입력하지 않아도 되길 원한다.
- 매월 1일~말일 기간을 지정해 정산 메시지를 멤버에게 일괄 전송하고 싶다.
- 멤버별로 이번 달에 얼마씩 냈는지 한눈에 보고 싶다.

**페인 포인트**: 멤버가 지출 사진을 단체 채팅방에 올리면 나중에 찾기가 너무 힘들다.

## 4. 기능 요구사항

> 도메인 정의서(1-domain-definition.md)의 비즈니스 규칙(BR), 데이터 규칙(DR)을 기반으로 작성한다.  
> 각 요구사항은 해당 규칙 ID를 참조한다.

### 4.1 회원 관리

|-------|---------|----------|---------|
| FR-U01 | 이메일 + 비밀번호로 회원가입 (v1 구현은 이메일 인증 없이 가입 즉시 이용 가능. 인증은 향후 과제) | 도메인 2.1 | Must |
| FR-U02 | 이메일 + 비밀번호로 로그인 | 도메인 2.1 | Must |
| FR-U03 | `username`은 서비스 전체에서 유일하게 설정 | DR-01 | Must |
| FR-U04 | 사용자 탈퇴 시 `inactive` 상태로 전환 (물리 삭제 없음). **탈퇴 즉시 모든 활성 세션(Refresh Token)을 삭제**하여 토큰 재발급을 차단한다. (이미 발급된 Access Token은 만료(최대 1시간)까지 유효할 수 있다.) | BR-12 | Must |

### 4.2 그룹 관리

### 4.3 멤버 초대

| FR-ID | 요구사항 | 근거 규칙 | 우선순위 |
|-------|---------|----------|---------|
| FR-I01 | MANAGER가 `username`으로 사용자 검색 후 초대 발송 | BR-03 | Must |
| FR-I02 | 초대는 발송 후 7일 간 유효, 경과 시 자동 만료 | 도메인 3.4 | Must |
| FR-I03 | 초대받은 사용자는 수락/거절 선택 가능 | 도메인 3.4 | Must |
| FR-I04 | 초대 수락 시 즉시 MEMBER로 그룹 합류 | BR-03 | Must |
| FR-I05 | 동일 대상에 PENDING 초대가 이미 있으면 중복 초대 차단 | 도메인 3.4 | Must |
| FR-I06 | MANAGER는 기존 멤버를 그룹에서 제거 가능. 제거된 멤버의 기존 지출·ExpenseSplit 레코드는 보존되나, 이후 정산의 집계 대상은 현재 그룹 멤버로 한정된다. 제거 후 해당 멤버는 그룹 지출 조회 불가. | BR-04 | Must |

> **멤버 제거 후 데이터 처리 규칙**
> - 기존 `Expense`(결제자로 등록된 지출 포함)와 `ExpenseSplit`은 삭제되지 않고 보존된다.
> - 제거 이후 신규 지출 입력 시 해당 멤버는 참여자 목록에서 제외된다.
> - 제거된 멤버가 결제자인 지출의 분담금은 잔여 멤버에게 재배분하지 않는다(원본 유지).

### 4.5 카테고리 관리

| FR-ID | 요구사항 | 근거 규칙 | 우선순위 |
|-------|---------|----------|---------|
| FR-C01 | 아래 표의 시스템 기본 카테고리 7개를 모든 그룹에 공통 제공 | BR-10 | Must |
| FR-C02 | SYSTEM 카테고리는 수정·삭제 불가 | BR-10 | Must |
| FR-C03 | MANAGER는 그룹 전용 카테고리 추가·삭제 가능 | BR-11 | Must |
| FR-C04 | GROUP 카테고리 삭제 시 해당 지출은 '기타'로 자동 재분류 | BR-11 | Must |

**시스템 기본 카테고리 확정 목록 (Single Source of Truth)**

> 이 목록은 DB 시드 데이터, 프론트엔드 UI, QA 테스트 케이스의 단일 기준이다.

| 순서 | 카테고리명 | 설명 |
|------|-----------|------|
| 1 | 식비 | 식사, 음료, 카페 등 |
| 2 | 교통 | 대중교통, 택시, 주유, 주차 등 |
| 3 | 숙소 | 호텔, 게스트하우스, 에어비앤비 등 |
| 4 | 쇼핑 | 의류, 생활용품, 기념품 등 |
| 5 | 문화/여가 | 영화, 공연, 관광, 스포츠 등 |
| 6 | 의료 | 병원, 약국, 의료 용품 등 |
| 7 | 기타 | 분류 불명확한 지출 및 GROUP 카테고리 삭제 시 재분류 대상 |

> `기타`는 삭제 불가인 동시에, GROUP 카테고리 삭제 시 자동 재분류 대상 카테고리로 사용된다.

## 8. 메시지 발송 정책

### 8.1 v1 — 인앱 메시지

- 정산 완료 시 그룹 내 **전 멤버**에게 인앱 메시지로 정산 완료 안내 발송 (개인별 금액은 정산 상세에서 확인)
- 메시지 수신 목록은 서비스 내에서 조회 가능
- 사용자 간 임의 메시지 기능 미제공 (정산 메시지 전용)

**정산 메시지 포함 내용 (현재 구현)**

| 항목 | 예시 |
|------|------|
| 안내 문구 + 정산 기간 | 정산이 완료되었습니다. (기간: 2026-06-15 ~ 2026-06-18) |

그룹명, 내 지불 금액, 내 분담금, 차액은 메시지 본문에 포함하지 않으며, 정산 상세 화면에서 확인한다. (개인화 요약은 향후 개선 과제)

### 8.2 v2 — 이메일 발송 (예정)

- 정산 메시지를 이메일로도 수신할 수 있는 옵션 추가
- 사용자 설정에서 이메일 알림 수신 여부 선택 가능
