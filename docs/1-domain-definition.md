# 도메인 정의서 — 공동 가계부 서비스

**버전:** 1.2  
**작성일:** 2026-06-17  

---

## 1. 서비스 개요

공동 가계부 서비스는 가족, 친구, 여행 그룹 등 복수의 사람이 함께 지출을 기록하고 정산할 수 있는 웹 기반 서비스이다. 개인 예산 계획은 다루지 않으며, **그룹 단위의 지출 기록과 정산**에 집중한다.

- **대상 사용자:** 가족 / 친구 / 여행 그룹 등 공동 지출이 발생하는 모든 유형의 그룹
- **예상 규모:** 초기 수십~수백 명, 이후 다수 사용자로 확장 가능한 구조
- **플랫폼:** 반응형 웹 UI (데스크톱 + 모바일 웹)

## 2. 유비쿼터스 언어 (Ubiquitous Language)

| 용어 | 정의 |
|------|------|
| **사용자 (User)** | 서비스에 가입한 개인. 사용자명(username)으로 식별된다. |
| **그룹 (Group)** | 공동 지출을 공유하는 사용자 집합. 하나의 사용자는 여러 그룹에 속할 수 있다. |
| **그룹 유형 (Group Type)** | 그룹의 운영 기간 성격. **기간 한정 그룹**과 **상시 그룹**으로 구분된다. |
| **기간 한정 그룹** | 시작일과 종료일이 있는 그룹 (예: 여행). 기간 종료 후 신규 지출 입력이 불가하다. |
| **상시 그룹** | 종료일 없이 지속 운영되는 그룹 (예: 가족). 매월 자동 월별 정산이 수행된다. |
| **그룹 관리자 (Admin)** | 그룹을 생성하거나 관리자 권한을 부여받은 멤버. 그룹 설정 변경 및 멤버 관리 권한을 가진다. 그룹 내 복수 존재 가능. |
| **그룹 멤버 (Member)** | 그룹에 속한 일반 사용자. 지출 입력 및 조회가 가능하다. |
| **지출 (Expense)** | 그룹 내에서 발생한 하나의 지출 건. 금액·카테고리·날짜·결제자·입력자·참여자·첨부파일을 포함한다. |
| **결제자 (Payer)** | 실제 대금을 지불한 멤버. 입력자와 다를 수 있다. |
| **입력자 (Creator)** | 지출 항목을 시스템에 등록한 멤버. |
| **참여자 (Participant)** | 해당 지출의 혜택을 공유하는 멤버. 정산 시 분담 대상이 된다. |
| **분담액 (Share Amount)** | 지출 총액을 참여자 수로 균등 분할한 개인별 부담액. 원 단위 반올림 후 오차는 결제자가 부담한다. |
| **카테고리 (Category)** | 지출을 분류하는 태그. 시스템 제공 기본 카테고리와 그룹 단위 커스텀 카테고리로 구분된다. |
| **정산 (Settlement)** | 특정 기간의 지출을 집계하여 멤버 간 채권·채무 관계를 확정하는 행위. |
| **정산 주기 (Settlement Period)** | 정산 대상 기간. 상시 그룹은 매월 자동 생성되고, 기간 한정 그룹은 관리자가 수동 실행한다. |
| **정산 내역 (Settlement Item)** | 특정 정산 주기 내에서 한 멤버가 다른 멤버에게 지급해야 하는 금액 단위. |
| **정산 완료 (Settlement Confirmed)** | 해당 정산 내역의 실제 송금이 이루어졌음을 **송금 당사자(from_member)** 가 확인한 상태. |
| **초대 (Invitation)** | 관리자가 사용자명으로 대상을 검색하여 그룹 가입을 요청하는 행위. 대상자가 수락해야 그룹 멤버가 된다. |

## 3. 핵심 도메인 개념 및 규칙

### 3.1 사용자 (User)

- 이메일과 비밀번호로 가입하며, 서비스 내에서 **사용자명(username)** 으로 식별된다.
- 사용자명은 유일하며, 멤버 초대 시 검색 키로 사용된다.
- 한 사용자는 여러 그룹에 동시 소속될 수 있다.

### 3.2 그룹 (Group)

그룹 생성 시 아래 두 가지 유형 중 하나를 선택한다.

| 속성 | 기간 한정 그룹 | 상시 그룹 |
|------|--------------|---------|
| 시작일 | 필수 | 생성일로 자동 설정 |
| 종료일 | 필수 | 없음 |
| 정산 방식 | **수동** (관리자가 실행) | **자동** (매월 1일 전월 집계) |
| 지출 입력 | 종료일 이전만 허용 | 제한 없음 |
| 중간 정산 | 종료 전이라도 수동 정산 가능 | 해당 없음 (자동 월별 처리) |
| 대표 사례 | 여행, 단기 이벤트 | 가족, 정기 모임 |

- 그룹 생성자는 자동으로 **그룹 관리자**가 된다.
- 그룹 관리자는 다른 멤버에게 관리자 권한을 추가로 부여할 수 있으며, 권한 부여 후에도 원 관리자의 권한은 유지된다 (복수 관리자 허용).
- 모든 멤버는 그룹 내 전체 지출 내역을 조회할 수 있다 (전체 공개).
- **기간 한정 그룹**은 종료일 자정(KST 00:00)에 자동으로 ARCHIVED 상태가 된다.
- **상시 그룹**은 관리자가 수동으로 비활성화(ARCHIVED)할 수 있다.
- 그룹 삭제 기능은 제공하지 않는다. ARCHIVED 상태의 데이터는 3년간 보존된다.

### 3.3 멤버 초대 및 탈퇴

#### 초대 흐름
1. 그룹 관리자가 사용자명으로 대상을 검색하여 초대 요청을 전송한다.
2. 초대받은 사용자는 인앱 알림으로 초대를 확인하고 **수락** 또는 **거절**을 선택한다.
3. 수락 시 해당 그룹의 멤버로 등록된다. 거절 시 초대는 무효화된다.
4. 초대는 발송 후 **7일** 이 경과하면 자동 만료된다.
5. 동일 대상에게 중복 초대는 발송할 수 없다 (PENDING 상태의 초대가 이미 존재하는 경우).

#### 탈퇴 및 강퇴
- 멤버는 언제든지 스스로 그룹에서 탈퇴할 수 있다.
- 그룹 관리자는 멤버를 강퇴할 수 있다.
- 탈퇴 또는 강퇴된 멤버가 기록한 지출, 참여자로 포함된 지출 내역은 **삭제되지 않고 그대로 보존**된다.
- 탈퇴한 멤버는 지출 내역에서 `(탈퇴한 사용자)`로 익명화 표시된다.
- 그룹의 마지막 관리자는 다른 멤버에게 관리자 권한을 이전하기 전까지 탈퇴할 수 없다.

### 3.4 지출 (Expense)

지출 한 건은 다음 속성으로 구성된다.

| 속성 | 설명 | 필수 여부 |
|------|------|---------|
| 금액 | 지출 총액 (원화 정수) | 필수 |
| 카테고리 | 기본 또는 커스텀 카테고리 | 필수 |
| 날짜 | 지출 발생 일자 | 필수 |
| 결제자 | 실제 대금을 지불한 그룹 멤버 | 필수 |
| 입력자 | 지출을 시스템에 등록한 멤버 (자동 기록) | 자동 |
| 참여자 | 지출을 공유하는 멤버 목록 (결제자 포함 가능) | 필수 (1인 이상) |
| 메모 | 지출에 대한 부가 설명 | 선택 |
| 첨부파일 | 영수증 또는 관련 사진 (복수 첨부 가능) | 선택 |

**분담액 계산 규칙**
- `개인 분담액 = round(지출 금액 ÷ 참여자 수)` (원 단위 반올림)
- 반올림 오차로 발생하는 총액 불일치는 결제자가 부담한다.
- 예: 10,000원 ÷ 3명 = 3,333원 × 2명 + 3,334원(결제자 부담) = 10,000원

**지출 수정·삭제 규칙**
- **입력자 본인** 또는 **그룹 관리자**만 수정·삭제할 수 있다.
- 기간 한정 그룹에서는 그룹 종료일 이후 날짜의 지출은 입력할 수 없다.

### 3.5 카테고리 (Category)

**기본 카테고리** (시스템 전체 공통, 수정·삭제 불가):

| 카테고리명 |
|-----------|
| 식비 |
| 교통 |
| 숙박 |
| 쇼핑 |
| 문화/여가 |
| 의료 |
| 기타 |

**커스텀 카테고리 규칙**
- 그룹 관리자 또는 일반 멤버 모두 그룹 단위로 커스텀 카테고리를 **추가**할 수 있다.
- 커스텀 카테고리 **수정·삭제**는 그룹 관리자만 가능하다.
- 커스텀 카테고리는 해당 그룹에서만 사용된다.
- 커스텀 카테고리 삭제 시, 해당 카테고리에 연결된 기존 지출 기록은 보존된다.

### 3.6 정산 (Settlement)

#### 상시 그룹 — 자동 정산
- 매월 1일 00:00에 이전 월의 지출을 집계하여 정산 내역을 자동 생성한다.
- 정산 내역 생성 후 모든 그룹 멤버에게 인앱 알림을 전송한다.
- 알림에는 정산 요약(총 지출액, 개인별 분담액, 송금 대상 및 금액)이 포함된다.

#### 기간 한정 그룹 — 수동 정산
- 그룹 관리자가 언제든지 수동으로 정산을 실행할 수 있다 (종료 전 중간 정산 포함).
- 정산 실행 시 지정한 기간의 지출을 집계하여 정산 내역을 생성한다.
- 정산 실행 시 모든 그룹 멤버에게 인앱 알림을 전송한다.

#### 공통 정산 규칙
- 정산 내역은 `(보내야 할 멤버, 받아야 할 멤버, 금액)` 단위로 구성된다.
- 동일 기간에 대해 정산이 이미 존재하면 중복 실행할 수 없다.
- **정산 완료 체크는 송금 당사자(from_member) 본인만** 가능하다.
- 정산 히스토리는 영구적으로 조회 가능하다.

### 3.7 알림 (Notification)

- **채널:** 인앱 알림 (MVP 범위). 이메일 알림은 이후 확장 고려.
- **발송 시점:**
  - 그룹 초대 요청 수신 시
  - 초대 수락/거절 결과 (초대 발송자에게)
  - 정산 내역 생성 시 (전 멤버)
  - 초대 만료 시 (초대 발송자에게)
  - 자동 정산 배치 실패 시 (해당 그룹 관리자에게, BATCH_FAILURE)

### 3.8 리포트 및 내보내기

- **파이 차트**: 지정한 기간 동안의 카테고리별 지출 비율을 시각화한다.
- **기간 필터**: 시작일~종료일 범위를 자유롭게 지정할 수 있다.
- **엑셀 내보내기**: 파이 차트와 **동일한 기간 필터**를 적용한 결과를 `.xlsx` 파일로 다운로드한다.
  - 포함 컬럼: 날짜, 카테고리, 금액, 결제자, 참여자, 메모

## 5. 도메인 모델 개요

```
User
 ├─ id (UUID)
 ├─ username (unique)
 └─ email

Group
 ├─ id (UUID)
 ├─ name
 ├─ type: LIMITED | ONGOING
 ├─ status: ACTIVE | ARCHIVED
 ├─ start_date
 └─ end_date (type=LIMITED인 경우만)

GroupMember
 ├─ group_id    → Group
 ├─ user_id     → User
 ├─ role        : ADMIN | MEMBER
 └─ is_active   (탈퇴/강퇴 여부)

GroupInvitation
 ├─ id (UUID)
 ├─ group_id    → Group
 ├─ inviter_id  → GroupMember (초대 발송자)
 ├─ invitee_id  → User (초대 대상)
 ├─ status      : PENDING | ACCEPTED | REJECTED | EXPIRED
 └─ expires_at  (발송일 + 7일)

Category
 ├─ id
 ├─ name
 ├─ type        : DEFAULT | CUSTOM
 └─ group_id    → Group (CUSTOM인 경우만)

Expense
 ├─ id (UUID)
 ├─ group_id     → Group
 ├─ payer_id     → GroupMember (결제자)
 ├─ created_by   → GroupMember (입력자)
 ├─ amount
 ├─ category_id  → Category
 ├─ expense_date
 └─ memo

ExpenseParticipant
 ├─ expense_id   → Expense
 ├─ member_id    → GroupMember
 └─ share_amount

ExpenseAttachment
 ├─ expense_id   → Expense
 └─ file_url (Object Storage 경로)

Settlement
 ├─ id (UUID)
 ├─ group_id     → Group
 ├─ period_start
 ├─ period_end
 └─ type         : AUTO | MANUAL

SettlementItem
 ├─ settlement_id → Settlement
 ├─ from_member   → GroupMember (송금 당사자)
 ├─ to_member     → GroupMember
 ├─ amount
 └─ is_confirmed  (from_member가 완료 체크)

Notification
 ├─ id (UUID)
 ├─ user_id      → User (수신자)
 ├─ type         : INVITATION | SETTLEMENT | INVITATION_RESULT | INVITATION_EXPIRED | BATCH_FAILURE
 ├─ ref_id       (관련 엔티티 ID)
 ├─ is_read
 └─ created_at
```

## 8. 주요 결정 사항 (Decision Log)

| # | 항목 | 결정 내용 |
|---|------|---------|
| D-01 | 기간 한정 그룹 정산 | 자동 정산 없음. 관리자가 수동 실행 (종료 전 중간 정산 포함) |
