## 1. 화면 구조 개요

```
서비스
├── 인증 (AuthLayout)
│   ├── /login              로그인
│   └── /signup             회원가입
│
└── 앱 (AppLayout — 인증 필수, ProtectedRoute)
    ├── /groups                              그룹 목록
    ├── /groups/new                          그룹 생성
    ├── /groups/:groupId                     그룹 상세 (정보 탭: 그룹 정보·멤버 목록·초대 폼)
    │   ├── /groups/:groupId/expenses        지출 목록 탭
    │   ├── /groups/:groupId/expenses/new    지출 입력
    │   ├── /groups/:groupId/expenses/:expenseId/edit  지출 수정
    │   ├── /groups/:groupId/settlements     정산 탭 (실행·목록·상세)
    │   └── /groups/:groupId/categories      카테고리 탭 (카테고리 관리)
    ├── /invitations                         수신 초대 목록
    ├── /messages                            메시지 목록
    ├── /reports                             리포트 (그룹 선택 + 기간 지정)
    └── /settings/withdraw                   계정 설정 (비밀번호 변경·회원 탈퇴)
```

> 그룹 수정은 별도 라우트가 없고 그룹 상세의 모달로 처리한다. 그룹 상세 탭은 **정보 / 지출 / 정산 / 카테고리** 4개이다.

### 구현 현황 — 와이어프레임과 실제 화면의 차이

아래 절의 ASCII 와이어프레임은 초기 설계안이며, 실제 구현은 다음과 같이 다르다. 충돌 시 이 표와 실제 코드가 우선한다.

| 절 | 와이어프레임(설계) | 실제 구현 |
|----|-------------------|----------|
| 3 (AppLayout) | 사용자명 드롭다운, 콘텐츠 최대 768px | 높이 56px 헤더에 로고·가로 내비(그룹 목록/초대함/보고서)·메시지 벨(배지)·계정 설정·로그아웃, 콘텐츠 최대 1200px(그룹 상세 등은 더 좁음), 모바일은 햄버거 드로어 |
| 4-3 (탈퇴) | `/withdraw`, 이메일 표시 | `/settings/withdraw`, 사용자명만 표시, 비밀번호 변경 영역 포함 |
| 5-1 (그룹 목록) | 카드에 멤버 수·역할 | '기간제/상시', 상태, '관리자/멤버' 배지와 기간(`YYYY-MM-DD ~`). 멤버 수는 카드에 없음 |
| 5-2 (그룹 생성) | UNLIMITED 선택 시 시작일·종료일 숨김 | UNLIMITED 선택 시 **종료일만** 숨김(시작일은 항상 표시), 기본 선택은 UNLIMITED |
| 5-3 (그룹 상세) | 지출/정산/멤버/카테고리/리포트 5탭 | **정보 / 지출 / 정산 / 카테고리** 4탭. 멤버 목록과 초대 폼은 정보 탭, 리포트는 `/reports` |
| 5-4 (그룹 수정) | `/groups/:id/edit` 별도 화면, 유형 변경 불가 표시, 위험 영역 | 그룹 상세의 수정 모달(이름·시작일·종료일), 비활성화는 상단 버튼 + 확인 모달 |
| 6-2 (초대 발송) | 별도 화면, 대기 중 초대 목록 | 정보 탭 하단 인라인 폼(username 입력 + 전송). 대기 중 초대 목록 UI 없음 |
| 6-3 (수신 초대) | 만료 초대는 비활성 버튼 | PENDING 초대만 표시하고, 만료된 초대는 버튼 없이 '만료됨' 배지 |
| 7-1 (지출 목록) | 건수 표시, 모바일 하단 고정 버튼 | 건수·하단 고정 버튼 없음(상단 '지출 등록'). 기본 조회 기간은 **그룹 시작일~종료일**(상시 그룹은 종료일 제한 없음). 필터는 클라이언트에서 적용 |
| 7-2 (지출 폼) | 결제자 선택 | 결제자 드롭다운(참여자 중 선택, 기본값은 입력자)의 선택값이 요청의 `paid_by`로 전송된다. 서버는 결제자가 그룹 멤버인지 검증하고, 수정·삭제 권한은 입력자(`created_by`) 기준이다 |
| 8 (카테고리) | 그룹 설정에서 진입 | 그룹 상세의 '카테고리' 탭에서 진입(`/groups/:id/categories`). GROUP 카테고리 삭제는 MANAGER만 가능 |
| 9-1 (정산 실행) | 모달 내 날짜 입력 | MANAGER에게 인라인 폼을 보여주고, 실행 시 확인 모달 |
| 9-2·9-3 (정산 목록·상세) | '재정산' 라벨·총 지출, 별도 상세 화면, 엑셀 2종 | 목록 항목을 펼치는 아코디언 상세, 정산 상세의 엑셀 버튼은 '정산 금액' 1종(지출 엑셀은 지출 목록에서 제공) |
| 10 (메시지) | 그룹명·결제액·분담액·차액·상세 링크 | 안내 문구(기간 제거), 정산 기간, 정산일만 표시 |
| 11 (리포트) | 그룹 상세 탭, 조회 버튼, 비율 컬럼, 엑셀 2종 | 별도 `/reports`에서 그룹·기간 선택 후 자동 조회, **PDF 내보내기**만 제공(엑셀은 지출 목록·정산 상세) |
| 12 (토스트) | 성공/경고/에러 | `success` / `error` / `info` 3종, 우측 하단, 닫기 버튼 |

## 2. 반응형 기준

### 브레이크포인트

| 이름 | 범위 | 대상 기기 |
|------|------|----------|
| `mobile` | 320px ~ 767px | 스마트폰 |
| `tablet` | 768px ~ 1023px | 태블릿 |
| `desktop` | 1024px 이상 | PC / 노트북 |

> 와이어프레임은 **mobile(320px)** 과 **desktop(1024px+)** 두 뷰를 기준으로 작성한다.  
> 별도 표기가 없는 단일 뷰는 두 환경에서 레이아웃 차이 없이 동일하게 표시된다.

### 반응형 공통 규칙

| 규칙 | mobile | desktop |
|------|--------|---------|
| 콘텐츠 최대 너비 | 100% (좌우 16px 패딩) | 768px 중앙 정렬 |
| 터치 타깃 최소 크기 | **44×44px** (WCAG 2.5.5) | 32×32px |
| 날짜 입력 2개 나란히 배치 | **세로 스택** (각각 100% 너비) | 가로 나란히 (`~ `구분자) |
| 버튼 + 입력 필드 나란히 | **세로 스택** (버튼 100% 너비) | 가로 나란히 |
| 테이블 다열(4열 이상) | **카드형 목록**으로 전환 | 테이블 형태 유지 |
| 탭 5개 (그룹 상세) | **가로 스크롤** 또는 `더보기 ▾` | 5개 탭 전체 노출 |
| 모달 너비 | **화면 100% - 32px 여백** | 최대 480px 중앙 |
| 엑셀 내보내기 버튼 2개 | **세로 스택** | 가로 나란히 |

### 모바일 전용 패턴

- **하단 고정 주요 액션 버튼**: `[+ 지출 입력]`, `[정산 실행]` 등 주요 CTA는 모바일에서 화면 하단 고정 (`position: fixed; bottom: 16px`)
- **스와이프 삭제**: 지출 목록 카드에서 좌로 스와이프 시 [삭제] 버튼 노출 (선택적 구현)
- **날짜 피커**: 모바일에서는 네이티브 `<input type="date">` 사용, 데스크탑은 커스텀 달력 컴포넌트

                              │   잠시 후 다시 시도해 주세요.  │
                              └───────────────────────────────┘
```

### 로딩 상태

```
버튼 수준:  [ ⟳ 저장 중... ]  ← 클릭 비활성화
페이지 수준: (화면 중앙 스피너)
```

### 빈 상태

```
┌──────────────────────────────────────────────┐
│                                              │
