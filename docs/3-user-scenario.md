## 1. 인증

### SC-01. 신규 회원가입

- **액터:** 비회원 사용자
- **사전 조건:** 서비스에 가입되어 있지 않다.
- **트리거:** 사용자가 회원가입 화면에서 가입 정보를 입력하고 가입 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 사용자가 이메일, 비밀번호, 사용자명(username)을 입력한다.
2. 시스템이 이메일 형식, 비밀번호 규칙(최소 8자, 영문+숫자 조합), 사용자명 중복 여부를 검증한다.
3. 시스템이 계정을 생성하고 로그인 화면으로 이동시킨다.

**예외/대안 흐름:**
- E1. 이메일 형식이 유효하지 않은 경우: "올바른 이메일 주소를 입력해 주세요." 메시지를 표시하고 입력 필드에 포커스를 유지한다.
- E2. 비밀번호가 최소 8자 미만이거나 영문·숫자 조합을 충족하지 못하는 경우: "비밀번호는 8자 이상의 영문과 숫자 조합이어야 합니다." 메시지를 표시한다.
- E3. 이미 사용 중인 이메일인 경우: "이미 사용 중인 이메일입니다." 메시지를 표시한다.
- E4. 이미 사용 중인 사용자명인 경우: "이미 사용 중인 사용자명입니다. 다른 이름을 입력해 주세요." 메시지를 표시한다.
- E5. 사용자명을 입력하지 않은 경우: "사용자명은 필수 입력 항목입니다." 메시지를 표시한다.

- **사후 조건:** 새 계정이 생성되고, 사용자는 로그인 화면으로 이동한다.

### SC-02. 이메일·비밀번호 로그인

- **액터:** 가입된 사용자
- **사전 조건:** 사용자가 서비스에 가입되어 있다.
- **트리거:** 사용자가 로그인 화면에서 이메일과 비밀번호를 입력하고 로그인 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 사용자가 이메일과 비밀번호를 입력한다.
2. 시스템이 자격증명을 검증한다.
3. 시스템이 Access Token(유효 1시간)과 Refresh Token(유효 30일)을 발급한다.
4. 사용자가 그룹 목록(홈) 화면으로 이동한다.

**예외/대안 흐름:**
- E1. 이메일 또는 비밀번호가 일치하지 않는 경우: "이메일 또는 비밀번호가 올바르지 않습니다." 메시지를 표시하고 비밀번호 필드를 초기화한다.
- E2. 입력 필드가 비어 있는 경우: 각 필드에 "필수 입력 항목입니다." 메시지를 표시한다.

- **사후 조건:** 유효한 Access Token과 Refresh Token이 발급되며, 사용자는 홈 화면에 진입한다.

---

### SC-03. Access Token 자동 갱신 및 강제 로그아웃

- **액터:** 로그인 상태의 사용자, 시스템
- **사전 조건:** 사용자가 로그인되어 있으며 Access Token이 만료 임박 또는 만료 상태이다.
- **트리거:** 사용자가 인증이 필요한 API를 호출한다.

**기본 흐름 (Happy Path):**
1. 시스템이 Access Token 만료를 감지한다.
2. 시스템이 유효한 Refresh Token을 사용하여 새 Access Token을 자동 발급한다.
3. 사용자는 별도 조작 없이 서비스를 계속 이용한다.

**예외/대안 흐름:**
- E1. Refresh Token도 만료된 경우: 시스템이 현재 화면에서 세션 만료 안내를 표시하고, 사용자를 로그인 화면으로 이동시킨다(강제 로그아웃).

- **사후 조건:** (기본 흐름) 새 Access Token이 발급되어 세션이 유지된다. (E1) 사용자 세션이 종료되고 로그인 화면으로 이동한다.

---

### SC-04. 로그아웃

- **액터:** 로그인 상태의 사용자
- **사전 조건:** 사용자가 로그인되어 있다.
- **트리거:** 사용자가 마이페이지/설정 화면에서 로그아웃 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 시스템이 서버측 Refresh Token을 무효화한다.
2. 클라이언트의 토큰 정보가 삭제된다.
3. 사용자가 로그인 화면으로 이동한다.

**예외/대안 흐름:**
- 없음.

- **사후 조건:** Refresh Token이 무효화되고, 해당 토큰으로 더 이상 갱신할 수 없다.

---

### SC-05. 비밀번호 재설정

- **액터:** 비밀번호를 분실한 사용자
- **사전 조건:** 사용자가 가입된 이메일 주소를 알고 있다.
- **트리거:** 사용자가 로그인 화면에서 "비밀번호를 잊으셨나요?" 링크를 클릭하고 이메일을 입력한다.

**기본 흐름 (Happy Path):**
1. 사용자가 비밀번호 재설정 화면에서 가입 이메일을 입력하고 전송 버튼을 누른다.
2. 시스템이 해당 이메일로 재설정 링크를 발송한다. 링크는 1시간 유효하다.
3. 사용자가 이메일의 링크를 클릭하여 새 비밀번호 입력 화면으로 이동한다.
4. 사용자가 새 비밀번호를 입력하고 확인 버튼을 누른다.
5. 시스템이 비밀번호를 변경하고 링크를 즉시 무효화한다.
6. 사용자가 새 비밀번호로 로그인 화면에 진입한다.

**예외/대안 흐름:**
- E1. 가입되지 않은 이메일을 입력한 경우: 정보 노출 방지를 위해 "해당 이메일로 재설정 링크를 발송했습니다." 메시지를 동일하게 표시한다(실제 이메일은 발송되지 않음).
- E2. 재설정 링크가 만료된 경우(1시간 초과): "링크가 만료되었습니다. 비밀번호 재설정을 다시 요청해 주세요." 안내를 표시하고, 재설정 화면으로 이동시킨다.
- E3. 이미 사용된 링크로 재접근하는 경우: "이미 사용된 링크입니다." 안내를 표시한다.
- E4. 새 비밀번호가 규칙(최소 8자, 영문+숫자 조합)을 충족하지 못하는 경우: 유효성 오류 메시지를 표시하고 입력을 차단한다.

- **사후 조건:** 비밀번호가 변경되며, 재설정 링크는 즉시 무효화된다. 기존 Refresh Token은 모두 무효화된다.

### SC-06. 회원 탈퇴

- **액터:** 로그인 상태의 사용자 (이지민)
- **사전 조건:** 사용자가 로그인되어 있다. 탈퇴 대상 사용자가 모든 그룹에서 마지막 관리자가 아닌 상태이다.
- **트리거:** 이지민이 마이페이지/설정에서 회원 탈퇴를 요청한다.

**기본 흐름 (Happy Path):**
1. 이지민이 탈퇴 확인 다이얼로그에서 탈퇴 사유를 확인하고 확인 버튼을 누른다.
2. 시스템이 이지민의 개인정보(이메일, 사용자명 등)를 즉시 삭제한다.
3. 이지민이 입력하거나 참여자로 기록된 지출 내역은 보존되며, 표시 이름이 `(탈퇴한 사용자)`로 변경된다.
4. 시스템이 Refresh Token을 무효화하고 로그인 화면으로 이동시킨다.

**예외/대안 흐름:**
- E1. 탈퇴하려는 사용자가 특정 그룹의 마지막 관리자인 경우: "관리자 권한을 다른 멤버에게 이전한 후 탈퇴할 수 있습니다." 안내를 표시하고 탈퇴를 차단한다.

- **사후 조건:** 계정의 개인정보가 삭제되고, 연관 지출 기록은 익명화된다.

## 2. 그룹 관리

### SC-07. 그룹 생성 — 기간 한정 그룹

- **액터:** 로그인 상태의 사용자 (이지민)
- **사전 조건:** 이지민이 로그인되어 있다.
- **트리거:** 이지민이 홈 화면에서 "그룹 만들기" 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 이지민이 그룹 생성 화면에서 그룹 유형으로 "기간 한정"을 선택한다.
2. 그룹 이름, 시작일, 종료일을 입력한다. (예: "제주 여행", 2026-07-10 ~ 2026-07-14)
3. 시스템이 그룹을 생성하고, 이지민을 해당 그룹의 관리자로 자동 등록한다.
4. 이지민이 생성된 그룹의 상세 화면(지출 목록)으로 이동한다.

**예외/대안 흐름:**
- E1. 그룹 이름을 입력하지 않은 경우: "그룹 이름은 필수 입력 항목입니다." 메시지를 표시한다.
- E2. 종료일이 시작일보다 이전인 경우: "종료일은 시작일 이후여야 합니다." 메시지를 표시한다.
- E3. 기간 한정 그룹에서 종료일을 입력하지 않은 경우: "기간 한정 그룹은 종료일을 반드시 입력해야 합니다." 메시지를 표시한다.

- **사후 조건:** 새 기간 한정 그룹(ACTIVE 상태)이 생성되고, 이지민은 해당 그룹의 유일한 관리자(ADMIN)로 등록된다.

---

### SC-08. 그룹 생성 — 상시 그룹

- **액터:** 로그인 상태의 사용자 (김태우)
- **사전 조건:** 김태우가 로그인되어 있다.
- **트리거:** 김태우가 홈 화면에서 "그룹 만들기" 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 김태우가 그룹 생성 화면에서 그룹 유형으로 "상시"를 선택한다.
2. 그룹 이름을 입력한다. (예: "우리 가족 생활비")
3. 종료일 항목은 표시되지 않으며, 시작일은 오늘 날짜로 자동 설정된다.
4. 시스템이 그룹을 생성하고 김태우를 관리자로 등록한다.
5. 김태우가 그룹 상세 화면으로 이동한다.

**예외/대안 흐름:**
- E1. 그룹 이름을 입력하지 않은 경우: "그룹 이름은 필수 입력 항목입니다." 메시지를 표시한다.

- **사후 조건:** 새 상시 그룹(ACTIVE 상태)이 생성되고, 김태우는 관리자로 등록된다. 매월 1일 자동 정산 배치가 이 그룹을 대상으로 동작한다.

### SC-09. 멤버 초대

- **액터:** 그룹 관리자 (이지민)
- **사전 조건:** 이지민이 그룹의 관리자이고, 초대 대상자가 서비스에 가입되어 있다.
- **트리거:** 이지민이 멤버 관리 화면에서 "멤버 초대" 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 이지민이 사용자명 검색창에 초대하려는 사람의 username을 입력한다.
2. 시스템이 일치하는 사용자를 검색 결과로 표시한다.
3. 이지민이 검색 결과에서 대상자를 선택하고 초대 버튼을 누른다.
4. 시스템이 초대 요청(PENDING)을 생성하고, 대상자에게 인앱 알림을 전송한다.
5. 이지민에게 "초대를 전송했습니다." 확인 메시지를 표시한다.

**예외/대안 흐름:**
- E1. 검색된 사용자가 이미 그룹 멤버인 경우: "이미 그룹에 참여 중인 멤버입니다." 안내를 표시하고 초대를 차단한다.
- E2. 검색된 사용자에게 이미 PENDING 상태의 초대가 존재하는 경우: "이미 초대 요청이 진행 중입니다." 안내를 표시하고 중복 초대를 차단한다.
- E3. 검색한 사용자명에 해당하는 사용자가 없는 경우: "해당 사용자명을 찾을 수 없습니다." 메시지를 표시한다.

- **사후 조건:** PENDING 상태의 초대가 생성되고, 초대 대상자에게 알림이 전송된다. 초대는 7일 후 자동 만료된다.

---

### SC-10. 초대 수락

- **액터:** 초대받은 사용자
- **사전 조건:** 사용자가 PENDING 상태의 초대를 보유하고 있다.
- **트리거:** 사용자가 메시지함에서 초대 알림을 확인하고 "수락" 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 사용자가 메시지함에서 초대 알림을 열어 그룹명, 초대한 관리자 이름을 확인한다.
2. "수락" 버튼을 누른다.
3. 시스템이 초대 상태를 ACCEPTED로 변경하고, 해당 그룹의 MEMBER로 등록한다.
4. 초대 발송자(이지민)에게 수락 결과 알림을 전송한다.
5. 사용자가 홈 화면에서 새로 가입된 그룹을 확인할 수 있다.

**예외/대안 흐름:**
- E1. 초대 유효 기간(7일)이 지난 경우: "초대가 만료되었습니다. 관리자에게 다시 초대를 요청하세요." 안내를 표시하고, 수락·거절 버튼을 비활성화한다.
- A1. 사용자가 "거절" 버튼을 누르는 경우: 초대 상태가 REJECTED로 변경되고, 초대 발송자에게 거절 결과 알림이 전송된다.

- **사후 조건:** (수락 시) 사용자가 그룹 멤버(MEMBER)로 등록된다. (거절 시) 초대가 REJECTED 상태로 종료된다.

---

### SC-11. 초대 자동 만료 처리

- **액터:** 시스템
- **사전 조건:** PENDING 상태의 초대가 발송된 지 7일이 경과했다.
- **트리거:** 시스템 배치가 만료 대상 초대를 감지한다.

**기본 흐름 (Happy Path):**
1. 시스템이 만료 대상 초대의 상태를 EXPIRED로 변경한다.
2. 시스템이 초대 발송자에게 "초대가 만료되었습니다." 인앱 알림을 전송한다.

**예외/대안 흐름:**

## 3. 지출 관리

### SC-17. 지출 등록

- **액터:** 그룹 멤버 (이지민)
- **사전 조건:** 이지민이 ACTIVE 상태의 그룹에 소속되어 있다.
- **트리거:** 이지민이 그룹 상세 화면에서 "지출 등록" 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 이지민이 지출 등록 화면에서 아래 정보를 입력한다.
   - 금액: 45,000원
   - 카테고리: 식비
   - 날짜: 2026-07-11
   - 결제자: 이지민(본인)
   - 참여자: 이지민, 박민준, 최수현 (3명)
   - 메모: "점심 삼겹살"
2. 시스템이 분담액을 계산한다. 45,000 ÷ 3 = 15,000원 (오차 없음).
3. 이지민이 저장 버튼을 누른다.
4. 지출이 등록되고 그룹 상세 화면의 지출 목록에 추가된다.

**예외/대안 흐름:**
- E1. 금액이 0 이하이거나 입력되지 않은 경우: "금액은 1원 이상이어야 합니다." 메시지를 표시한다.
- E2. 참여자를 선택하지 않은 경우: "참여자를 1명 이상 선택해야 합니다." 메시지를 표시한다.
- E3. 기간 한정 그룹에서 지출 날짜가 종료일 이후인 경우: "그룹 종료일 이후 날짜의 지출은 등록할 수 없습니다." 메시지를 표시한다.
- E4. 그룹이 ARCHIVED 상태인 경우: 지출 등록 버튼이 비활성화되거나 표시되지 않는다.
- A1. 결제자가 입력자(이지민)와 다른 경우: 결제자 드롭다운에서 다른 멤버를 선택하여 진행한다. 흐름은 동일하다.

- **사후 조건:** 지출 항목이 저장되고, 참여자별 분담액(round(금액 ÷ 참여자수))이 계산된다. 반올림 오차는 결제자 부담으로 기록된다.

### SC-18. 분담액 반올림 오차 처리 확인

- **액터:** 시스템
- **사전 조건:** 지출 금액이 참여자 수로 나누어 떨어지지 않는다.
- **트리거:** 지출 등록 시 분담액 계산이 실행된다.

**기본 흐름 (Happy Path):**
1. 김태우가 10,000원짜리 지출을 3명 참여로 등록한다.
2. 시스템이 round(10,000 ÷ 3) = 3,333원으로 분담액을 계산한다.
3. 나머지 2명은 각각 3,333원이 분담액으로 기록된다.
4. 오차(10,000 - 3,333 × 3 = 1원)는 결제자(김태우)가 추가 부담하므로, 결제자의 분담액은 3,334원으로 기록된다.

**예외/대안 흐름:**
- 없음.

- **사후 조건:** 분담액의 합계가 지출 총액과 일치한다. 오차는 결제자에게 귀속된다.

### SC-23. 커스텀 카테고리 수정 및 삭제

- **사후 조건:** 커스텀 카테고리가 수정되거나 삭제된다. 삭제 시 기존 지출 기록은 보존된다.

- **액터:** 그룹 관리자 (이지민)
- **사전 조건:** 이지민이 기간 한정 그룹의 관리자이고, 정산할 기간에 지출이 존재한다.
- **트리거:** 이지민이 정산 실행 화면에서 기간을 지정하고 "정산 실행" 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 이지민이 정산 실행 화면에 진입한다.
2. 정산 기간이 기본값(마지막 정산 다음 날 ~ 오늘)으로 설정되어 있다.
3. 이지민이 필요에 따라 기간을 조정하고 "정산 실행" 버튼을 누른다.
4. 시스템이 정산 알고리즘(순 채권채무 계산 후 최소 거래 수 그리디 방식)을 적용하여 송금 목록을 생성한다.
5. 정산 결과 화면에서 총 지출액, 개인별 분담액, 송금 대상 및 금액을 확인한다.
6. 시스템이 전체 멤버에게 정산 생성 인앱 알림을 전송한다.

**예외/대안 흐름:**
- E1. 이미 동일 기간에 정산이 존재하는 경우: "해당 기간은 이미 정산되었습니다. 기간을 변경해 주세요." 안내를 표시하고 정산 실행을 차단한다.
- E2. 지정한 기간에 지출이 없는 경우: "해당 기간에 지출 내역이 없습니다." 안내를 표시한다.
- E3. 일반 멤버가 정산 실행을 시도하는 경우: "정산 실행 권한이 없습니다." 안내를 표시하고 버튼을 노출하지 않는다.

- **사후 조건:** 정산 내역(SettlementItem 목록)이 생성되고, 모든 멤버에게 정산 알림이 전송된다.

### SC-25. 상시 그룹 — 자동 월별 정산 생성

- **액터:** 시스템
- **사전 조건:** 상시 그룹(ACTIVE)이 존재하고, 이전 월에 지출이 기록되어 있다.
- **트리거:** 매월 1일 00:00 KST 배치 작업이 실행된다.

**기본 흐름 (Happy Path):**
1. 시스템이 ACTIVE 상태의 모든 상시 그룹을 조회한다.
2. 각 그룹별로 전월 지출을 집계하여 정산 내역을 자동 생성한다(type: AUTO).
3. 그룹 내 모든 멤버에게 정산 생성 인앱 알림을 전송한다.
4. 알림에는 총 지출액, 개인별 분담액, 송금 대상 및 금액이 포함된다.

**예외/대안 흐름:**
- E1. 배치 실행 중 오류가 발생하는 경우: 시스템이 해당 그룹 관리자에게 BATCH_FAILURE 알림을 전송한다. 관리자는 수동 재실행을 통해 정산을 처리할 수 있다.
- E2. 전월에 지출이 없는 경우: 해당 그룹의 정산을 생략하거나, "지출 내역이 없어 정산이 생성되지 않았습니다." 처리한다.

- **사후 조건:** 자동 정산 내역이 생성되고, 멤버들에게 알림이 전송된다.

---

### SC-26. 배치 실패 후 관리자 수동 재실행

- **액터:** 그룹 관리자 (김태우)
- **사전 조건:** 자동 정산 배치가 실패하여 김태우에게 BATCH_FAILURE 알림이 수신된 상태이다.
- **트리거:** 김태우가 알림을 확인하고 정산 화면에서 "정산 재실행" 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 김태우가 BATCH_FAILURE 알림을 확인한다.
2. 정산 화면으로 이동하여 실패한 정산 기간을 확인한다.
3. "재실행" 버튼을 눌러 정산을 수동으로 재실행한다.
4. 시스템이 정산 내역을 생성하고, 전체 멤버에게 알림을 전송한다.

**예외/대안 흐름:**
- E1. 재실행 중 동일 기간에 이미 정산이 존재하는 경우(중복 방지): "해당 기간은 이미 정산되었습니다." 안내를 표시한다.

- **사후 조건:** 실패했던 정산이 완료되고 멤버들에게 알림이 전송된다.

### SC-27. 정산 완료 체크

- **액터:** 송금 당사자 (from_member)
- **사전 조건:** 정산 내역이 생성되어 있고, 로그인한 사용자가 해당 정산 내역의 from_member이다.
- **트리거:** 사용자가 정산 결과 또는 정산 히스토리 화면에서 "송금 완료" 체크 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 사용자가 본인이 송금해야 할 정산 내역을 확인한다.
2. "송금 완료" 버튼을 누른다.
3. 시스템이 해당 SettlementItem의 is_confirmed를 true로 변경한다.
4. 화면에 "완료" 상태가 표시된다.

**예외/대안 흐름:**
- E1. 다른 멤버(to_member 또는 제3자)가 체크를 시도하는 경우: 체크 버튼이 비활성화되거나 표시되지 않는다. API 호출 시 "본인의 송금 건만 완료 처리할 수 있습니다." 오류를 반환한다.

- **사후 조건:** SettlementItem의 is_confirmed가 true로 변경된다.

### SC-28. 정산 히스토리 조회

- **액터:** 그룹 멤버 (이지민)
- **사전 조건:** 이지민이 그룹에 소속되어 있고, 정산 내역이 하나 이상 존재한다.
- **트리거:** 이지민이 정산 히스토리 화면으로 이동한다.

**기본 흐름 (Happy Path):**
1. 시스템이 해당 그룹의 모든 정산 목록을 최신순으로 표시한다.
2. 이지민이 특정 정산을 선택하면 해당 기간의 총 지출액, 개인별 분담액, 송금 내역 및 완료 여부를 확인한다.

**예외/대안 흐름:**
- E1. 정산 내역이 없는 경우: "아직 정산 내역이 없습니다." 안내를 표시한다.

- **사후 조건:** 없음 (조회만 수행). 정산 히스토리는 영구 보존된다.

## 6. 인앱 알림

### SC-29. 알림 목록 조회 및 미읽 확인

- **액터:** 로그인 상태의 사용자 (김태우)
- **사전 조건:** 김태우에게 전달된 알림이 하나 이상 존재한다.
- **트리거:** 김태우가 메시지함 아이콘을 누른다.

**기본 흐름 (Happy Path):**
1. 시스템이 김태우의 모든 알림을 최신순으로 표시한다.
2. 읽지 않은 알림은 시각적으로 구분된다(예: 강조 표시 또는 배지).
3. 김태우가 알림을 누르면 해당 알림이 읽음 처리된다.

**예외/대안 흐름:**
- E1. 알림이 없는 경우: "알림이 없습니다." 안내를 표시한다.

- **사후 조건:** 열람한 알림의 is_read가 true로 변경된다.

### SC-30. 초대 알림에서 바로 수락/거절

- **액터:** 초대받은 사용자
- **사전 조건:** 사용자에게 그룹 초대 알림이 수신되어 있다.
- **트리거:** 사용자가 메시지함에서 초대 알림을 열람한다.

**기본 흐름 (Happy Path):**
1. 알림 상세에서 그룹명과 초대한 관리자 이름을 확인한다.
2. "수락" 또는 "거절" 버튼이 알림 내에 표시된다.
3. 사용자가 "수락" 버튼을 누른다.
4. 시스템이 초대를 ACCEPTED로 처리하고 그룹 멤버로 등록한다.
5. 초대 발송자에게 수락 결과 알림이 전송된다.
6. 해당 그룹이 사용자의 홈 화면 그룹 목록에 추가된다.

**예외/대안 흐름:**
- E1. 이미 만료된 초대 알림을 열람하는 경우: "이 초대는 만료되었습니다." 안내를 표시하고 수락/거절 버튼을 비활성화한다.
- A1. 사용자가 "거절" 버튼을 누르는 경우: 초대가 REJECTED 처리되고, 발송자에게 거절 알림이 전송된다.

- **사후 조건:** (수락) 사용자가 그룹 멤버로 등록된다. (거절) 초대가 REJECTED 상태로 종료된다.

### SC-31. 정산 생성 알림 수신

- **액터:** 그룹 멤버 전체
- **사전 조건:** 정산이 생성(자동 또는 수동)되었다.
- **트리거:** 시스템이 정산 생성 직후 알림을 발송한다.

**기본 흐름 (Happy Path):**
1. 시스템이 그룹 내 모든 활성 멤버에게 인앱 알림을 전송한다.
2. 알림에는 총 지출액, 개인별 분담액, 본인의 송금 대상 및 금액이 포함된다.
3. 멤버가 알림을 열람하면 정산 결과 화면으로 이동한다.

**예외/대안 흐름:**
- 없음.

- **사후 조건:** 멤버들이 정산 내용을 알림을 통해 인지한다.

### SC-32. 배치 실패 알림 수신

- **사전 조건:** 자동 정산 배치 실행 중 오류가 발생했다.
- **트리거:** 시스템이 BATCH_FAILURE 알림을 관리자에게 전송한다.

**기본 흐름 (Happy Path):**
1. 김태우의 메시지함에 BATCH_FAILURE 알림이 표시된다.
2. 알림을 열람하면 실패한 그룹과 대상 기간 정보가 표시된다.
3. "정산 재실행" 링크 또는 버튼을 통해 정산 화면으로 이동한다.

**예외/대안 흐름:**
- 없음.

- **사후 조건:** 관리자가 배치 실패를 인지하고 수동 재실행을 수행할 수 있다.

### SC-33. 카테고리별 파이 차트 조회

- **액터:** 그룹 멤버 (이지민)
- **사전 조건:** 이지민이 그룹에 소속되어 있고, 해당 기간에 지출이 하나 이상 존재한다.
- **트리거:** 이지민이 리포트 화면으로 이동하여 기간을 지정한다.

**기본 흐름 (Happy Path):**
1. 이지민이 리포트 화면에서 시작일과 종료일을 설정한다. (예: 2026-07-10 ~ 2026-07-14)

3. 카테고리별 금액과 비율을 파이 차트로 시각화하여 표시한다.
4. 차트 하단 또는 범례에 카테고리명, 금액, 비율이 함께 표시된다.

**예외/대안 흐름:**
- E1. 지정 기간에 지출이 없는 경우: "해당 기간에 지출 내역이 없습니다." 안내를 표시한다.
- E2. 종료일이 시작일보다 이전인 경우: "종료일은 시작일 이후여야 합니다." 메시지를 표시하고 조회를 차단한다.

- **사후 조건:** 없음 (조회만 수행).

### SC-34. 지출 내역 엑셀(.xlsx) 내보내기

- **액터:** 그룹 멤버 (김태우)
- **사전 조건:** 김태우가 그룹에 소속되어 있고, 리포트 화면에서 기간이 설정되어 있다.
- **트리거:** 김태우가 리포트 화면에서 "엑셀 내보내기" 버튼을 누른다.

**기본 흐름 (Happy Path):**
1. 시스템이 현재 파이 차트에 적용된 기간 필터와 동일한 범위의 지출 데이터를 조회한다.
2. 다음 컬럼을 포함한 .xlsx 파일을 생성한다: 날짜, 카테고리, 금액, 결제자, 참여자, 메모.
3. 파일이 자동으로 다운로드된다.

**예외/대안 흐름:**
- E1. 해당 기간에 지출이 없는 경우: "내보낼 지출 내역이 없습니다." 메시지를 표시하고 다운로드를 차단한다.
- E2. 파일 생성 중 서버 오류가 발생하는 경우: "파일 생성에 실패했습니다. 잠시 후 다시 시도해 주세요." 메시지를 표시한다.

- **사후 조건:** 지출 데이터가 담긴 .xlsx 파일이 사용자 기기에 저장된다.
